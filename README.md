# FileMind

Локальное настольное приложение на Python 3.11+ и PySide6 для Windows 10/11. Сканирование выбранной папки, поиск, сортировка целых папок по категориям, SHA-256-дубликаты, избранное и история SQLite. Содержимое файлов не загружается в сеть. Дополнительный AI-советчик отправляет в YandexGPT только предварительно показанные названия и структуру папок, имена файлов и описания рабочих пространств.

## Установка и запуск на Windows

Откройте PowerShell в папке проекта:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Можно использовать Python новее 3.11. Для обычной работы интернет нужен только для первоначального скачивания зависимостей. Для AI-советчика требуется доступ к API YandexGPT. Для Linux/macOS используйте `python3 -m venv .venv`, затем `.venv/bin/python` вместо Windows-пути.

## Работа с приложением

1. **Open Folder** (`Ctrl+O`) выбирает папку. Вложенные папки сканируются в фоне. **Cancel** останавливает задачу; при сканировании остаются уже найденные результаты. **Rescan Folder** (`F5`) обновляет список.
2. Таблица сортируется нажатием на заголовки. Двойной щелчок открывает файл стандартным приложением; контекстное меню открывает расположение или копирует путь. Файлы не запускаются без действия пользователя.
3. **Search Files** (`Ctrl+F`) и поля над таблицей фильтруют по имени, расширению, категории, размеру в MB и локальным датам изменения включительно. Нулевой максимум означает отсутствие ограничения. **Clear filters** очищает фильтры в текущем разделе; **All Files** возвращает все категории.
4. **Organize Folders** сортирует только непосредственные вложенные папки выбранного каталога, независимо от фильтра таблицы. Каждая папка перемещается целиком с прежней внутренней структурой. Отдельные файлы, скрытые папки и уже существующие категории (`Documents`, `Images`, `Videos`, `Audio`, `Archives`, `Code`, `Other`, `Projects`, `Folders`, `Workspaces`) остаются на месте. Папки с проектами попадают в `Projects`; папки с файлами одной категории — в эту категорию; смешанные и пустые — в `Folders`. Проект распознаётся по `.git`, `pyproject.toml`, `requirements.txt`, `package.json`, `Cargo.toml`, `go.mod`, `setup.py`, `setup.cfg`, `CMakeLists.txt`, `pom.xml`, `build.gradle`, `build.gradle.kts`, `Gemfile`, `composer.json` или `.sln`, в том числе во вложенных папках. Если выбран сам корень проекта, приложение предлагает выбрать его родительскую папку. Сначала показывается полный план, включая пометку **Whole folder**; только **Confirm moves** запускает перемещения. Совпадения получают имена `Папка (1)`, содержимое папок не объединяется. Повторная организация не затрагивает папки внутри категорий.

   Например, `Работа/МойСайт/src/main.py` становится `Работа/Projects/МойСайт/src/main.py`, а `Работа/Отпуск/2026/фото.jpg` — `Работа/Images/Отпуск/2026/фото.jpg`. Перенос проекта может потребовать пересоздания `.venv` и обновления внешних абсолютных ссылок.
5. **Find Duplicates** сначала группирует файлы по размеру, затем сравнивает SHA-256. Отметьте ненужные копии и нажмите **Remove selected copies**. После просмотра плана требуется отдельное подтверждение. Нельзя выбрать все копии в группе; содержимое проверяется повторно перед операцией.
6. Удаление реализовано как обратимое перемещение в `.filemind-trash` внутри выбранной папки. Эта папка исключена из сканирования. **Место на диске не освобождается**: для окончательного удаления удалите её содержимое вручную после проверки. Кнопки необратимого удаления в приложении нет.
7. **History → Restore selected move** восстанавливает одну папку целиком или один файл в прежнее расположение после подтверждения. Если содержимое перемещённого объекта изменено или прежнее имя занято, операция блокируется. Чтобы восстановить всю сортировку, возвращайте нужные строки истории по одной, начиная с последних.
8. **Save folder** добавляет текущую папку в **Favorites**. Двойной щелчок по избранному открывает папку. **Settings** сохраняет тему. Тёмная тема по умолчанию, оформление в `styles.qss`. Размер окна также сохраняется.

Overview показывает общий объём, количество и распределение по категориям вместе с таблицей. Code и Other доступны через фильтр категорий.

## AI-советчик и организации

YandexGPT предлагает, к какой организации или рабочему пространству относится папка. Программа сохраняет папки целиком и размещает их по пути `Workspaces/Организация/Категория/ИмяПапки`. Например, `Портал Альфа/src/main.py` станет `Workspaces/Альфа/Projects/Портал Альфа/src/main.py`. Две организации получают отдельные каталоги, даже если названия проектов совпадают. Обычная сортировка не затрагивает `Workspaces`.

1. Откройте **Tools → AI settings**. Укажите Yandex Cloud folder ID, имя модели (например, `yandexgpt/latest`) и API-ключ. Ключ сохраняется только в системном хранилище: Keychain на macOS, Credential Manager на Windows, Secret Service на Linux. При недоступности хранилища сохранение завершается ошибкой без копии ключа в файлах. Пустое поле ключа сохраняет существующий доступ.
2. Добавьте рабочие пространства, по одному на строку: `Название | Описание`. Укажите названия компаний, клиентов и проектов, по которым их можно различить. Эти описания сохраняются локально и включаются в запрос.
3. Выберите родительскую папку и нажмите **AI Advisor**. Анализируются непосредственные вложенные папки и папки внутри стандартных категорий (например, `Projects`). Сам корень проекта защищён; выберите его родителя. Существующие `Workspaces` пропускаются.
4. Просмотрите **точные данные запроса** и нажмите **Send to YandexGPT**. Передаются относительные названия папок, локально определённая категория, до 40 имён файлов из первых трёх уровней каждой папки и описания организаций. Содержимое файлов, абсолютные пути, скрытые файлы, `.git`, `.env`, `node_modules`, `venv` и `__pycache__` в эти сведения не входят; ссылки не обходятся. Анализ ограничен 30 папками и размером запроса. Имена файлов тоже могут содержать личные сведения — просмотр запроса позволяет решить, стоит ли их отправлять.
5. Проверьте предложения и объяснения AI. Неоднозначные папки получают **Leave in place / needs clarification**. Вы можете изменить организацию вручную. **Review move plan** показывает точные пути и переименования при конфликтах; только **Confirm moves** запускает переносы. История и восстановление работают для папки целиком. Конфигурация организаций сохраняется между запусками; автоматического обучения по исправлениям пока нет.

AI получает указание не угадывать организацию по общему типу проекта. Это рекомендация модели, поэтому принадлежность нужно проверять в плане. Ответ проверяется локально: неизвестные организации, пропущенные и повторяющиеся папки, незавершённый ответ не принимаются. Пути назначения строит FileMind, AI не получает доступа к файловым операциям. При ошибке сети, отмене или отказе API переносы не начинаются. Сетевой запрос имеет таймаут 30 секунд; отмена во время запроса применяется после его завершения или таймаута.

Запросы тарифицируются Yandex Cloud. В каждом запросе передаётся `x-data-logging-enabled: false`, как описано в [документации Yandex AI Studio](https://aistudio.yandex.ru/en/docs/ai-studio/operations/disable-logging). Формат ответа задаётся JSON Schema через [Text Generation API](https://aistudio.yandex.ru/en/docs/ai-studio/text-generation/api-ref/TextGeneration/completion).

Для переноса доступа из другого вашего проекта без копирования ключа в репозиторий:

```sh
.venv/bin/python tools/import_yandex.py /path/to/your/project/.env
```

Импортируются только `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` и `YANDEX_MODEL`. Ключ уходит в системное хранилище FileMind; каталог и модель сохраняются в игнорируемом Git файле `.filemind-ai.json`. Исходный проект не изменяется. В собранном приложении настройки подключения вводятся через **AI settings**; локальный файл импорта в сборку не включён. Также поддерживаются переменные окружения `FILEMIND_YANDEX_API_KEY`, `FILEMIND_YANDEX_FOLDER_ID`, `FILEMIND_YANDEX_MODEL`.

Проверка подключения на вымышленных данных (один реальный платный запрос, без чтения пользовательских папок):

```sh
.venv/bin/python tools/check_yandex.py
```

## Сохранность файлов

- Сканируется только явно выбранная папка; приложение не запускает автоматическое сканирование при старте.
- При сканировании символические ссылки не обходятся. Ссылки внутри перемещаемой папки сохраняются как ссылки; внешние цели не изменяются. Абсолютные ссылки могут потребовать ручного обновления. Неподдерживаемые reparse points и специальные файлы блокируют перенос папки. Корни дисков и стандартные системные каталоги Windows защищены от организации.
- Папки переносятся атомарным переименованием без замены существующего назначения в пределах одной файловой системы. На Windows используется `os.rename`, на macOS — `renamex_np(RENAME_EXCL)`, на Linux — `renameat2(RENAME_NOREPLACE)`. При переносе между файловыми системами или отсутствии поддержки операция завершается ошибкой, исходная папка сохраняется. Перед переносом сохраняется отпечаток имён, содержимого файлов, прав, пустых папок и целей ссылок для проверки восстановления. Отдельные файлы при помещении дубликатов в карантин и восстановлении старых операций по-прежнему копируются с эксклюзивным созданием назначения и проверкой SHA-256, затем удаляется источник; для этого требуется временное место под дополнительную копию.
- Конфликт, появившийся после просмотра плана, приводит к ошибке, а не перезаписи.
- Отмена сохраняет завершённые перемещения в истории. Незавершённая копия удаляется, источник сохраняется. Ошибки отдельных файлов не останавливают всю очередь.
- При закрытии во время задачи сначала запрашивается её отмена. После завершения окно можно закрыть повторно.
- История записывается перед началом каждой операции. После аварийного отключения строки `pending` или `recovery_needed` требуют ручной проверки обоих путей: приложение не делает предположений о том, какая копия актуальна. Автоматическое восстановление таких строк отключено.
- Во время перемещений не редактируйте обрабатываемые файлы и не меняйте структуру папок другой программой. Проверки обнаруживают обычные изменения, но не обеспечивают транзакций между файловой системой, SQLite и другими процессами. Для важных данных нужна резервная копия.

Настройки, абсолютные пути избранного, пути перемещений, хеши для восстановления и диагностический журнал находятся в `%LOCALAPPDATA%\FileMind`. На macOS — `~/Library/Application Support/FileMind`, на Linux — `$XDG_DATA_HOME/FileMind` или `~/.local/share/FileMind`. Содержимое файлов и индекс сканирования между запусками не сохраняются. Журнал ограничен размером и двумя резервными файлами.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Проверено в среде macOS с Python 3.13.5 и PySide6 6.12.0: **78 тестов проходят**, включая GUI в режиме Qt offscreen. Сборка и нативные диалоги Windows в этой среде не проверялись.

Тесты используют временные папки. Проверяют рекурсию, исключение ссылок и карантина, фильтры, хеширование, отмену, конфликты, восстановление, защиту последней копии, SQLite и открытие интерфейса со сканированием. Проверки AI используют имитацию API и хранилища ключей: отсутствие содержимого файлов в запросах, разделение организаций, ручная проверка плана, восстановление, неоднозначность, некорректные ответы, ошибки доступа и отмена. Обычный запуск pytest не обращается к YandexGPT и не читает ключ из системного хранилища. Дополнительно проверяются перенос целых проектов, вложенная структура, скрытые файлы, пустые папки, ссылки, классификация папок, повторная сортировка, конфликт с пустой папкой назначения, отмена и восстановление папок. Для создания символических ссылок на Windows включите Developer Mode или запускайте тесты с соответствующим правом.

## Сборка EXE

Собирать Windows EXE нужно **на Windows**, в активном окружении с установленным `requirements-dev.txt`:

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --windowed --name FileMind --add-data "styles.qss;." main.py
```

Результат: `dist\FileMind\FileMind.exe`. Передавайте пользователю всю папку `dist\FileMind`, а не только EXE. Вариант одного файла:

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onefile --windowed --name FileMind --add-data "styles.qss;." main.py
```

Результат: `dist\FileMind.exe`. Проверяйте сборку на Windows 10/11, включая выбор папки, открытие файла в стандартном приложении и восстановление пробной сортировки. Подпись кода и установщик в проект не входят.

## Структура

```text
filemind/
├── main.py                 # запуск и журнал
├── main_window.py          # окно, модели таблиц, диалоги
├── filesystem.py           # ссылки и reparse points Windows
├── models.py               # записи файлов и категории
├── file_scanner.py         # рекурсивное чтение без ссылок
├── file_organizer.py       # план, безопасные перемещения и восстановление
├── folder_organizer.py     # категории папок, отпечатки и атомарный перенос
├── duplicate_finder.py     # SHA-256 и группы
├── ai_advisor.py           # метаданные, YandexGPT, проверка ответов и план
├── ai_settings.py          # доступ в системном хранилище и настройки
├── ai_dialogs.py           # организации, просмотр запроса и рекомендаций
├── tools/                  # импорт подключения и живая проверка на тестовых данных
├── file_search.py          # независимые фильтры
├── database.py             # SQLite
├── workers.py              # фоновые QThread и отмена
├── settings.py             # каталог данных
├── styles.qss              # тёмная тема
├── requirements.txt
├── requirements-dev.txt
├── pytest.ini
└── tests/
    ├── test_core.py
    ├── test_ai.py
    ├── test_folders.py
    └── test_ui.py
```
